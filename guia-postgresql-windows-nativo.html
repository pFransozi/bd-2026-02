Instalando o PostgreSQL no Windows — sem Docker

Prepare um servidor PostgreSQL 18 diretamente no Windows, conecte pelo pgAdmin 4 e execute seu primeiro teste SQL. Este guia é uma alternativa ao ambiente com contêineres utilizado anteriormente.

0 · Escolha a instalação

Quais ferramentas utilizaremos?

Este guia prepara o PostgreSQL 18 diretamente no Windows, utilizando o instalador gráfico. O servidor será instalado como serviço do Windows. O pgAdmin 4 é a ferramenta gráfica utilizada para criar bancos e executar SQL.

Como utilizar este roteiro

Execute cada passo na ordem apresentada. Os comandos indicados como PowerShell são digitados no terminal do Windows; os comandos SQL são executados no Query Tool do pgAdmin. Confira o resultado de cada etapa antes de avançar.

pgAdmin 4Cliente gráfico no Windows
→
PostgreSQL 18Serviço local · porta 5432 ou 5433
↔
Banco laboratorioTabelas e dados persistidos em disco
O que será instalado?

Servidor PostgreSQL, pgAdmin 4 (caso ainda não esteja instalado) e ferramentas de linha de comando. Não será necessário instalar WSL ou utilizar contêineres.

Resultado ao final

Você terá um servidor em funcionamento, o usuário aluno, o banco laboratorio e uma tabela de teste pronta para consultas.

Este roteiro é uma alternativa ao guia anterior. Ambos permitem realizar a Prática Guiada 10. Escolha apenas um ambiente para trabalhar e mantenha suas informações de conexão organizadas.

1 · Verifique antes

O computador está pronto?

  1. Utilize Windows 10 ou Windows 11 de 64 bits. Verifique se sua conta permite instalar programas como administrador; computadores institucionais podem exigir suporte da equipe de TI.
  2. Confira se o PostgreSQL já está instalado: procure por PostgreSQL e pgAdmin 4 no menu Iniciar. Se já tiver um servidor funcionando, não reinstale automaticamente; passe para o diagnóstico da conexão.
  3. Abra o PowerShell e confira se a porta padrão está em uso.
PowerShell · verificar a porta padrão
Get-NetTCPConnection -LocalPort 5432 -State Listen -ErrorAction SilentlyContinue
Como interpretar a saída

Se não aparecer nenhuma linha, não há um processo escutando nessa porta neste momento. Se aparecer um resultado, outro serviço poderá estar usando 5432. Identifique-o antes de instalar; se necessário, configure o novo PostgreSQL na porta 5433 durante a instalação. Depois use essa mesma porta no pgAdmin e no Python.

Não é preciso alterar o firewall para acesso remoto: nesta prática utilizaremos apenas 127.0.0.1 (a própria máquina). Evite expor o serviço à rede sem necessidade.

2 · Obtenha o instalador

Baixe o PostgreSQL para Windows

  1. Acesse a página oficial de download para Windows.
  2. Clique em Download the installer. O download é disponibilizado pelo projeto parceiro EDB.
  3. Selecione PostgreSQL 18 para Windows x86-64 e baixe o instalador interativo.
  4. Após o download, localize o arquivo .exe na pasta Downloads. Não execute instaladores de sites desconhecidos.
Página oficial do PostgreSQL →Página de instaladores da EDB →
Não precisa baixar o pgAdmin à parte

O instalador do PostgreSQL para Windows permite selecionar o pgAdmin 4 como componente. Se você já possui uma versão funcional, pode mantê-la.

3 · Instalação nativa

Execute o assistente de instalação

Abra o instalador com permissões administrativas. As telas podem variar ligeiramente conforme a versão, mas os campos principais são os mesmos.

Etapa do assistenteComo preencher
Installation DirectoryMantenha a pasta sugerida, normalmente C:\Program Files\PostgreSQL\18.
Select ComponentsMarque PostgreSQL Server, pgAdmin 4 e Command Line Tools. Stack Builder é opcional para esta prática.
Data DirectoryMantenha o diretório de dados sugerido, a menos que exista uma orientação específica do laboratório.
PasswordDefina uma senha para o usuário administrador do servidor, postgres. Guarde essa senha; você precisará dela na configuração inicial.
PortUse 5432 se estiver livre. Se já estiver ocupada por outro serviço, use 5433 e anote a escolha.
Advanced Options / LocalePara a prática, mantenha a configuração padrão apresentada pelo instalador.
Summary / InstallRevise as opções e conclua a instalação.
Existem duas senhas diferentes

A senha que você definir agora pertence ao usuário administrador postgres. Na etapa 5 criaremos o usuário didático aluno, com outra senha. Se o pgAdmin solicitar uma master password, essa é uma terceira senha, usada para proteger conexões salvas no aplicativo.

Ao finalizar, desmarque a opção de abrir o Stack Builder, caso apareça. Não precisamos instalar extensões adicionais nesta aula.

Permissão administrativa necessária

Se o Windows bloquear a instalação ou a criação do serviço, solicite permissão à equipe de TI. Não tente contornar políticas de segurança do computador.

4 · Servidor em execução

Confirme o serviço do PostgreSQL

  1. Abra o menu Iniciar e procure Serviços ou pressione Win + R, digite services.msc e confirme.
  2. Procure um serviço semelhante a postgresql-x64-18. O nome exato pode variar.
  3. Verifique se o estado é Em execução e, quando aplicável, se o tipo de inicialização é Automático.
  4. Para confirmar pelo PowerShell, execute:
PowerShell · listar serviços PostgreSQL
Get-Service | Where-Object { $_.Name -like "postgresql*" }

Se o serviço estiver parado, use a opção Iniciar na janela de Serviços (pode exigir administração). Se não aparecer nenhum serviço, revise a instalação.

Você também pode testar a resposta da porta do banco (substitua 5432 por 5433 se essa foi a porta escolhida):

PowerShell · comando opcional com o caminho padrão
& "C:\Program Files\PostgreSQL\18\bin\pg_isready.exe" -h 127.0.0.1 -p 5432
Verificação desta etapa

O pg_isready deve indicar que o servidor aceita conexões. Se aparecer “command not found” ou o arquivo não existir, confira o caminho da instalação e se marcou Command Line Tools.

5 · Configuração inicial

Crie o usuário aluno e o banco laboratorio

O instalador criou um usuário administrador chamado postgres. Para esta prática, vamos trabalhar com um usuário separado, chamado aluno, que poderá criar bancos de laboratório sem receber privilégios de superusuário.

5.1 · Entre como administrador no pgAdmin

  1. Abra o pgAdmin 4.
  2. Se o servidor aparecer no painel Servers, tente conectá-lo com a senha postgres definida no instalador.
  3. Se não aparecer, clique com o botão direito em Servers → Register → Server…. Em General, escolha o nome PostgreSQL 18 — Administração.
  4. Em Connection, configure Host 127.0.0.1, Port 5432 (ou sua porta), Maintenance database postgres, Username postgres e a senha definida na instalação. Clique em Save.
  5. Expanda Databases → postgres, selecione esse banco e abra Tools → Query Tool.

5.2 · Crie o usuário de laboratório

Copie o SQL abaixo no Query Tool do banco postgres e execute uma única vez.

SQL · criar a conta aluno
CREATE ROLE aluno
    WITH LOGIN CREATEDB
    PASSWORD 'AulaBD2026_Local!';
Senha apenas de laboratório

A senha acima foi escolhida para que a atividade seja igual nos dois guias. É uma credencial didática para conexão local: não use essa senha em sistemas externos ou de produção e não a compartilhe fora do contexto da disciplina.

O comando concede LOGIN e CREATEDB. Isso é suficiente para o aluno criar o banco da prática, sem transformá-lo em administrador de todo o servidor.

5.3 · Crie o banco laboratorio

  1. No painel lateral do pgAdmin, clique com o botão direito em Databases → Create → Database….
  2. Preencha Database com laboratorio e Owner com aluno.
  3. Clique em Save. Se necessário, clique com o botão direito em Databases → Refresh.
ObjetoNome/valor usadoFunção
Usuário administradorpostgresConfiguração inicial do servidor.
Usuário da práticaalunoExecutar SQL e criar o banco posterior pratica_salas.
Banco iniciallaboratorioPrimeiro teste SQL, separado do banco administrativo.
Se surgir “role aluno already exists”

Você provavelmente já criou o usuário nessa instância. Não repita CREATE ROLE. Para redefinir a senha dessa conta de laboratório, um administrador pode executar ALTER ROLE aluno WITH LOGIN CREATEDB PASSWORD 'AulaBD2026_Local!';. Não altere outras contas sem necessidade.

6 · Conexão como aluno

Registre uma conexão para o laboratório

Agora vamos utilizar a conta aluno, em vez da conta administrativa postgres. Isso também facilita acompanhar a Prática Guiada 10 sem mudar os arquivos Python.

  1. No painel Servers, clique com o botão direito em Register → Server….
  2. Na guia General, digite PostgreSQL — Laboratório (nativo).
  3. Na guia Connection, preencha os campos conforme a tabela a seguir.
CampoValor
Name (General)PostgreSQL — Laboratório (nativo)

Port5432 ou 5433, conforme a instalação

  1. Clique em Save. Expanda Servers → PostgreSQL — Laboratório (nativo) → Databases → laboratorio → Schemas → public.
  2. Selecione o banco laboratorio e abra Tools → Query Tool.
  3. Execute o comando abaixo para confirmar a identidade, o banco e a porta do servidor:
SQL · verificar a conexão
SELECT current_database() AS banco,
       current_user AS usuario,
       inet_server_port() AS porta,
       version();
Verificação desta etapa

O resultado deve mostrar laboratorio, aluno e a porta configurada (normalmente 5432). Se a consulta retornar postgres como usuário, você abriu a conexão administrativa, não a do laboratório.

7 · Primeiro teste SQL

Crie uma tabela e realize consultas

No Query Tool do banco laboratorio, execute os blocos abaixo na ordem. Para executar apenas um bloco, selecione seu texto e clique em ▶.

7.1 · Criar a tabela

SQL · criar tabela de exemplo
CREATE TABLE centro_distribuicao (
    id_centro INTEGER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    nome VARCHAR(80) NOT NULL,
    cidade VARCHAR(80) NOT NULL,
    capacidade_diaria INTEGER NOT NULL CHECK (capacidade_diaria > 0)
);

Observe PRIMARY KEY, que identifica cada registro, e CHECK, que impede capacidades inválidas.

7.2 · Inserir quatro registros

SQL · inserir dados
INSERT INTO centro_distribuicao (nome, cidade, capacidade_diaria)
VALUES
    ('CD Curitiba Norte', 'Curitiba', 600),
    ('CD Curitiba Sul', 'Curitiba', 800),
    ('CD São José', 'São José dos Pinhais', 650),
    ('CD Londrina', 'Londrina', 500);

7.3 · Consultar os registros

SQL · listar dados
SELECT id_centro, nome, cidade, capacidade_diaria
FROM centro_distribuicao
ORDER BY id_centro;
Resultado esperado

A consulta deve mostrar quatro centros de distribuição. Caso a tabela ainda não apareça no painel do pgAdmin, clique com o botão direito em Tables → Refresh.

7.4 · Retomar agrupamento e agregação

SQL · agrupamento por cidade
SELECT cidade,
       COUNT(*) AS total_centros,
       SUM(capacidade_diaria) AS capacidade_total
FROM centro_distribuicao
GROUP BY cidade
ORDER BY capacidade_total DESC;

Se a tabela já existir

Não execute novamente CREATE TABLE nem os quatro INSERT. Execute apenas as consultas para evitar registros duplicados.

8 · Uso no dia a dia

Como iniciar e parar o servidor?

Na instalação nativa, o PostgreSQL funciona como um serviço do Windows. Não é necessário abrir o pgAdmin para que o servidor exista ou para que o serviço continue ativo.

  1. Abra Serviços (services.msc).
  2. Localize o serviço do PostgreSQL, como postgresql-x64-18.
  3. Observe o estado e o tipo de inicialização. Se for necessário, use Iniciar ou Reiniciar (pode exigir privilégios administrativos).
  4. Após iniciar o serviço, reconecte pelo pgAdmin e execute a consulta de conferência.
SQL · conferir persistência
SELECT COUNT(*) AS total
FROM centro_distribuicao;
Verificação

O resultado esperado é 4, desde que a tabela tenha sido criada e preenchida apenas uma vez. Parar e iniciar o serviço não deve apagar os arquivos do banco.

Em casa ou no laboratório

Se o serviço estiver configurado como automático, ele normalmente iniciará com o Windows. O pgAdmin pode ser aberto somente quando for necessário executar SQL.

Backup e recuperação

Os dados persistem em disco, mas isso não dispensa cópias de segurança. O pgAdmin possui a opção Backup…, e o PostgreSQL oferece ferramentas como pg_dump e pg_restore.

9 · Diagnóstico

Problemas comuns e como verificar

ProblemaO que fazer
Instalador pede administradorUse uma conta autorizada ou solicite ajuda à equipe de TI. A instalação do serviço precisa de permissão adequada.
Porta 5432 ocupadaVerifique a porta com PowerShell. Identifique o processo que a usa ou instale o PostgreSQL na 5433; ajuste a porta também no pgAdmin e no .env da prática.
Connection refusedConfira se o serviço PostgreSQL está em execução e se host e porta correspondem à instalação.
Password authentication failed for user postgresUse a senha de administrador definida durante a instalação, não a senha didática do usuário aluno.
Password authentication failed for user alunoConfira se a conta aluno foi criada na instância correta e se está utilizando AulaBD2026_Local!.
Role aluno already existsO usuário já foi criado nessa instância. Não repita o comando CREATE ROLE.
Database laboratorio already existsNão crie o banco novamente. Abra a conexão que já existe e confira a propriedade Owner.
Permission denied to create databaseVerifique se o usuário aluno recebeu CREATEDB na etapa 5.
Relation already existsO SQL de criação já foi executado. Não execute o mesmo bloco novamente.
psql ou pg_isready não encontradoO instalador normalmente não adiciona o diretório bin ao PATH. Use o caminho completo ou configure o PATH corretamente.

Se você escolheu a porta 5433

É necessário utilizá-la nos locais em que se conecta ao servidor: campo Port do pgAdmin, comando pg_isready e variável PGPORT do Python.

Arquivo .env · quando usar a porta 5433
PGHOST=127.0.0.1
PGPORT=5433
PGDATABASE=pratica_salas
PGUSER=aluno
PGPASSWORD=AulaBD2026_Local!
Não apague os dados para corrigir a conexão

Problemas de senha ou de porta normalmente não exigem desinstalar o PostgreSQL, remover pastas de dados ou criar outro banco. Faça primeiro as verificações de serviço, porta, usuário e senha.
