Aula 07 Estado DML Integridade Referencial

Aula 07 · material de aprofundamento

Manipular dados é transformar o estado do banco sem romper suas regras

Na aula principal usamos INSERT, UPDATE e DELETE e observamos restrições sendo aceitas ou rejeitadas pelo SQLite. Aqui o foco é entender o que essas operações significam no modelo relacional e por que integridade não é apenas uma mensagem de erro, mas uma condição para que o banco permaneça em um estado válido.

Leitura conceitualDMLIntegridadeConstraintsSQLite
Pergunta central
O que significa dizer que uma alteração de dados é válida?

Uma operação não é correta apenas porque sua sintaxe foi aceita. O novo estado do banco também precisa respeitar as regras definidas para o domínio.

1 · Estrutura e estado

O esquema define possibilidades; os dados representam o estado atual

Depois da DDL, o banco possui uma estrutura. Quando começamos a inserir, alterar e excluir linhas, passamos a modificar a instância atual dessa estrutura.

Esquema e instância respondem a perguntas diferentes

O esquema descreve quais relações existem, quais atributos pertencem a cada uma, quais tipos são esperados e quais restrições precisam ser preservadas. A instância corresponde ao conjunto de valores armazenados em determinado momento.

Assim, a definição de RESERVA pode permanecer a mesma durante todo o semestre, enquanto as linhas presentes nessa relação mudam continuamente.

Esquema

O que pode existir

Define colunas, chaves, referências, obrigatoriedade e demais restrições estruturais.

Instância

O que existe agora

É o conjunto atual de usuários, salas, telefones, reservas e demais ocorrências armazenadas.

DML altera a instância, não o significado da relação

Quando inserimos uma reserva, não estamos redefinindo o que significa RESERVA. Estamos acrescentando uma nova ocorrência compatível com o esquema já definido. O mesmo vale para atualizações e exclusões.

Estado válido A→ DML →Estado válido B
Integridade pode ser vista como uma fronteira

As restrições definem quais estados são aceitos pelo banco. Uma operação que levaria o banco para fora desse conjunto deve ser rejeitada.

2 · DML como transformação de estado

INSERT, UPDATE e DELETE não fazem a mesma coisa

Os três comandos modificam dados, mas cada um altera a relação de uma forma diferente.

INSERT

Acrescenta uma nova tupla, desde que os valores informados produzam uma ocorrência válida.

UPDATE

Substitui valores em tuplas já existentes e precisa validar novamente as regras afetadas pela alteração.

DELETE

Remove tuplas e pode afetar outras relações quando existem referências para a ocorrência removida.

INSERT é uma tentativa de acrescentar um novo fato

Ao executar um INSERT, o SGBD precisa verificar se a nova tupla pode coexistir com as demais. Uma chave primária repetida, uma chave estrangeira sem correspondente ou um valor que viola um CHECK impedem que esse novo fato seja incorporado ao banco.

UPDATE pode modificar uma ou muitas tuplas

UPDATE trabalha sobre o conjunto de linhas que satisfaz a condição definida. O comando não possui a noção de "registro que eu queria alterar"; ele utiliza a expressão de seleção informada.

Escopo definido por condição
UPDATE reserva
SET situacao = 'cancelada'
WHERE id_reserva = 1;

A condição seleciona uma ocorrência específica porque id_reserva é chave. Se a condição identificar dez linhas, as dez serão atualizadas. Se não houver WHERE, todas as linhas da relação entram no conjunto alvo.

DELETE remove ocorrências, não "campos"

DELETE atua sobre tuplas completas. Para remover apenas um valor de uma coluna, normalmente usamos UPDATE, quando a estrutura permite esse novo valor. A exclusão de uma tupla também precisa considerar as relações que dependem dela.

WHERE não é um mecanismo de segurança

WHERE apenas define o conjunto de linhas sobre o qual a operação atuará. A segurança vem de formular corretamente esse predicado, conferir seu alcance e manter restrições adequadas no banco.

E onde entra SELECT?

SELECT não altera o estado do banco. Nesta disciplina ele aparece junto às operações de manipulação porque é a principal ferramenta para observar o estado atual, localizar as linhas que serão afetadas e verificar o resultado depois de uma alteração.

Por isso, a sequência SELECT → UPDATE/DELETE → SELECT não é uma exigência sintática da SQL. É uma disciplina operacional útil para tornar explícito o conjunto que será modificado.

3 · Integridade

Uma restrição descreve estados que o banco não deve aceitar

As constraints não existem apenas para produzir mensagens de erro. Elas registram regras que precisam continuar verdadeiras depois de cada modificação.

Integridade de entidade

A identidade de uma ocorrência precisa permanecer inequívoca. A chave primária impede que duas tuplas utilizem a mesma identidade e não admite valor nulo para a chave.

Integridade de domínio

Os valores de um atributo precisam respeitar o conjunto de valores considerado válido para aquela propriedade. Tipo, NOT NULL e CHECK ajudam a aproximar a estrutura do domínio representado.

Integridade referencial

Uma chave estrangeira representa uma referência para uma ocorrência de outra relação. Se uma reserva informa id_usuario = 17, a referência precisa apontar para um usuário existente, salvo quando o modelo permite valor nulo.

ConstruçãoO que expressaQuando é verificada
PRIMARY KEYIdentidade única da tupla.Em inserções e alterações da chave.
FOREIGN KEYReferência válida a outra relação.Em inserções, alterações e operações que atinjam a ocorrência referenciada.
NOT NULLO atributo precisa possuir valor.Quando a nova versão da tupla é produzida.
UNIQUEUm valor ou combinação não pode se repetir segundo a regra declarada.Em inserções e atualizações que possam criar repetição.
CHECKO valor precisa satisfazer uma expressão.Quando a linha é inserida ou modificada.
DEFAULTFornece um valor quando o atributo é omitido.Na criação da nova linha, quando aplicável.

DEFAULT não é a mesma coisa que uma regra de validação

DEFAULT ajuda a construir uma nova tupla quando um valor foi omitido. Ele não garante, sozinho, que todos os valores futuros sejam válidos. No exemplo da aula, DEFAULT 'ativa' fornece uma situação inicial, enquanto CHECK (situacao IN (...)) limita quais situações podem ser armazenadas.

Restrições se complementam

Uma única constraint raramente descreve todo o significado de um atributo. Em situacao, por exemplo, NOT NULL impede ausência de valor, DEFAULT fornece um valor inicial e CHECK restringe o conjunto de valores aceitos.

Rejeitar uma operação pode ser o comportamento correto

Quando o SGBD rejeita uma inserção ou atualização que viola uma regra, ele está preservando a consistência do modelo. O erro é evidência de que a restrição foi aplicada, não necessariamente de que o banco "falhou".

4 · Integridade referencial e ações de exclusão

Excluir uma ocorrência pode ter consequências em outras relações

Quando uma chave é referenciada, o banco precisa saber o que fazer se a ocorrência proprietária for removida.

Relação referenciada e relação que referencia

Em TELEFONE_USUARIO, a coluna id_usuario referencia USUARIO.id_usuario. USUARIO ocupa o papel de relação referenciada; TELEFONE_USUARIO contém a chave estrangeira.

Em RESERVA, tanto USUARIO quanto SALA são referenciados. A existência dessas referências faz com que uma exclusão no lado referenciado não seja uma decisão isolada.

RESTRICT

Protege a ocorrência referenciada

A exclusão é rejeitada enquanto existirem linhas dependentes que apontam para ela.

CASCADE

Propaga a exclusão

Ao remover a ocorrência referenciada, o SGBD remove também as linhas dependentes correspondentes.

SET NULL

Preserva a linha, remove a referência

A FK passa a ser nula, desde que a coluna permita NULL e essa situação faça sentido no domínio.

Por que TELEFONE_USUARIO usa CASCADE?

Na estrutura da aula, um telefone registrado nessa relação só existe como telefone de um usuário específico. Se o usuário for removido, manter a linha de telefone sem proprietário não representa um fato útil no modelo. ON DELETE CASCADE expressa essa dependência.

Por que RESERVA usa RESTRICT?

Uma reserva registra um fato do sistema que envolve usuário e sala. Apagar automaticamente todo o histórico de reservas ao excluir um usuário ou uma sala teria consequências diferentes. A opção RESTRICT obriga a resolver primeiro as referências existentes.

SituaçãoAçãoEfeito conceitual
Excluir usuário com telefonesON DELETE CASCADEOs telefones associados deixam de existir junto com o usuário.
Excluir usuário com reservasON DELETE RESTRICTA exclusão é bloqueada enquanto o histórico de reserva mantiver a referência.
Excluir sala com reservasON DELETE RESTRICTO banco impede que a referência de uma reserva passe a apontar para nada.
A ação referencial é uma decisão de modelagem

CASCADE, RESTRICT e SET NULL não são apenas opções de sintaxe. Cada escolha descreve o que deve acontecer com fatos dependentes quando a ocorrência referenciada deixa de existir.

No SQLite, a fiscalização de FKs precisa estar ativa na conexão

A declaração da chave estrangeira registra a regra na estrutura. Na configuração usada em aula, a conexão também executa PRAGMA foreign_keys = ON para ativar a verificação das restrições referenciais.

5 · O predicado define o alcance da mudança

UPDATE e DELETE são operações sobre conjuntos

Mesmo quando pensamos em "alterar um registro", a SQL continua operando sobre todas as tuplas que satisfazem uma condição.

A condição não identifica automaticamente uma única linha

Uma expressão como WHERE situacao = 'ativa' pode selecionar muitas reservas. Uma expressão sobre chave primária tende a selecionar no máximo uma, porque a unicidade já foi garantida pela estrutura.

Predicado seletivo

WHERE id_reserva = 1

Como id_reserva é chave, a condição alcança no máximo uma reserva.

Predicado amplo

WHERE situacao = 'ativa'

Pode atingir qualquer quantidade de linhas que esteja atualmente nessa situação.

Sem WHERE, o conjunto alvo é toda a relação

Em UPDATE e DELETE, a ausência de WHERE não torna o comando inválido. Ela apenas significa que nenhuma linha foi excluída do conjunto alvo.

Operação válida, mas de grande alcance
UPDATE reserva
SET situacao = 'cancelada';

O risco não está na sintaxe. Está no fato de a operação representar uma transformação muito maior do que a intenção original.

SELECT antes da alteração é uma forma de inspecionar o predicado

Executar primeiro um SELECT com a mesma condição permite observar quais linhas satisfazem o predicado antes da modificação. Essa prática aproxima a intenção do operador do conjunto real que a SQL atingirá.

Definir condição→SELECT→Conferir conjunto→UPDATE/DELETE→SELECT

6 · Banco e aplicação

Validar na aplicação e restringir no banco são responsabilidades complementares

Uma interface pode impedir muitos erros antes que o comando seja enviado, mas as regras estruturais importantes continuam úteis no próprio banco.

A aplicação conhece o fluxo de uso

Ela pode orientar preenchimento, exibir mensagens amigáveis, confirmar exclusões e impedir ações inadequadas na interface.

O banco conhece o estado persistido

O SGBD recebe operações de diferentes pontos da aplicação, scripts, integrações e ferramentas administrativas. Constraints mantêm regras fundamentais próximas dos dados que precisam respeitá-las.

Aplicação

Prevenir e explicar

Ajuda o usuário a formular uma operação válida antes de enviá-la ao banco.

Banco

Preservar invariantes

Recusa estados incompatíveis com as constraints declaradas, independentemente do caminho usado para chegar até ele.

Uma regra importante deve sobreviver à interface

Se a consistência depende apenas de um formulário específico, outro caminho de escrita pode produzir dados incompatíveis. Regras estruturais centrais devem estar representadas onde os dados são preservados.

Síntese conceitual

DML muda fatos; integridade limita quais mudanças são aceitáveis

Manipular dados é transformar a instância do banco sem perder as propriedades que tornam essa instância coerente com o modelo.

Estado

Os dados atuais formam uma instância do esquema e podem mudar continuamente.

DML

INSERT, UPDATE e DELETE transformam esse estado sobre conjuntos de tuplas.

Integridade

PK, FK, NOT NULL, UNIQUE, CHECK e ações referenciais restringem os estados que podem ser aceitos.
