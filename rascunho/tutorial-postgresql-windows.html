PostgreSQL no Windows com Docker e pgAdmin 4

Preparar um servidor PostgreSQL local em contêiner, conectar-se pelo pgAdmin 4 e executar as primeiras consultas. Não é necessário instalar o servidor PostgreSQL diretamente no Windows.

0 · Entenda a estrutura

Quais ferramentas utilizaremos?

O Docker Desktop executa o contêiner que contém o servidor PostgreSQL. O pgAdmin 4 é o aplicativo gráfico instalado no Windows que se conecta ao servidor. Um volume Docker mantém os dados mesmo se o contêiner for parado ou recriado.

pgAdmin 4Aplicativo no Windows
→
PostgreSQLContêiner Docker · porta 5432
↔
Volume de dadosPersistência gerenciada pelo Docker
Ao final, você deverá conseguir

Iniciar e parar o banco; registrar a conexão no pgAdmin; executar SQL e verificar que os dados permanecem após reiniciar o contêiner.

O que será instalado no Windows?

Docker Desktop e pgAdmin 4. O PostgreSQL será obtido por imagem oficial, sem instalador nativo do servidor.

1 · Antes de começar

Verifique o Windows e o WSL 2

Use preferencialmente Windows 11 de 64 bits, com virtualização habilitada e 8 GB de RAM ou mais. Em outros sistemas, confira os requisitos atuais do Docker Desktop. Se estiver em um laboratório institucional, pode ser necessário solicitar a habilitação do WSL 2 à equipe de TI.

  1. Abra o PowerShell e verifique a instalação do WSL:
PowerShell · verificação
wsl --version
  1. Se o WSL não estiver instalado, abra o PowerShell como administrador e execute:
PowerShell (administrador) · somente se necessário
wsl --install

Reinicie o computador, se solicitado. Para atualizar o WSL quando necessário:

PowerShell (administrador)
wsl --update
Se o WSL já estiver funcionando

Não há necessidade de reinstalá-lo. Verifique apenas a versão e prossiga para o Docker Desktop.

Referência oficial: requisitos e instalação do Docker Desktop no Windows.

2 · Instalação do Docker

Instale e inicie o Docker Desktop

  1. Baixe o Docker Desktop para Windows no site oficial.
  2. Execute o instalador. Utilize o backend WSL 2, quando solicitado.
  3. Abra o Docker Desktop e aguarde o mecanismo de contêineres iniciar.
  4. Abra o PowerShell e confirme a disponibilidade dos comandos:
PowerShell · verificação do ambiente
docker --version
docker compose version
docker info

O último comando deve retornar informações do servidor Docker. Se disser que não consegue se conectar ao Docker daemon, abra o Docker Desktop e verifique se o mecanismo está iniciado.

Importante

Usaremos contêineres Linux com WSL 2. Você não precisa instalar uma distribuição Ubuntu separadamente para executar esses comandos no PowerShell.

3 · Instalação do servidor

Crie e inicie o PostgreSQL com Docker Compose

O arquivo compose.yaml descreve qual imagem executar, a senha de laboratório, a porta de acesso e o volume persistente. Ele permite que os estudantes iniciem a mesma configuração.

Baixar compose.yaml

3.1 · Prepare a pasta

PowerShell · criar a pasta do projeto
New-Item -ItemType Directory -Force -Path "$HOME\postgres-laboratorio"
Set-Location "$HOME\postgres-laboratorio"
notepad compose.yaml

Quando o Bloco de Notas abrir, cole o conteúdo abaixo e salve como compose.yaml. Confirme que o Windows não acrescentou a extensão .txt. Você também pode baixar o arquivo pronto acima e colocá-lo nessa pasta.

compose.yaml · servidor PostgreSQL 18
services:
  db:
    image: postgres:18
    restart: unless-stopped
    environment:
      POSTGRES_USER: aluno
      POSTGRES_PASSWORD: "AulaBD2026_Local!"
      POSTGRES_DB: laboratorio
    ports:
      - "127.0.0.1:5432:5432"
    volumes:
      - postgres_dados:/var/lib/postgresql
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U aluno -d laboratorio"]
      interval: 5s
      timeout: 5s
      retries: 12

volumes:
  postgres_dados:
Por que este volume?

Na imagem oficial do PostgreSQL 18, o volume persistente deve ser montado em /var/lib/postgresql. O caminho usado em versões antigas é diferente. Evite trocar a versão principal da imagem sem antes estudar a migração dos dados.

Credenciais somente para laboratório

A senha aparece no arquivo para facilitar a atividade local. A porta está limitada a 127.0.0.1, não exposta deliberadamente à rede. Não reutilize essa senha ou este arquivo em produção.

3.2 · Inicie e confira o serviço

PowerShell · execute dentro da pasta do compose.yaml
docker compose config
docker compose up -d
docker compose ps

O comando up -d inicia o contêiner em segundo plano. Na primeira execução, o Docker fará o download da imagem. Aguarde o serviço indicar healthy antes de conectar pelo pgAdmin.

PowerShell · diagnóstico e conexão por linha de comando
docker compose logs --tail=30 db
docker compose exec db psql -U aluno -d laboratorio -c "SELECT current_database(), current_user;"

Se a última consulta mostrar o banco laboratorio e o usuário aluno, o servidor está respondendo.

4 · Acesso gráfico

Instale e conecte o pgAdmin 4

O pgAdmin é uma ferramenta de administração gráfica desenvolvida para o PostgreSQL. Neste tutorial, instalaremos a versão para Windows, fora do Docker.

  1. Baixe o instalador pelo site oficial do pgAdmin 4 e conclua a instalação.
  2. Abra o pgAdmin 4. Caso solicite uma master password, crie uma senha para proteger as conexões salvas no aplicativo. Ela é diferente da senha do banco.
  3. No painel Servers, clique com o botão direito e escolha Register → Server….
  4. Na guia General, digite um nome para identificar o servidor. Na guia Connection, configure os campos abaixo.
CampoValorSignificado
Name (General)PostgreSQL — LaboratórioNome visual escolhido por você.
Host name/address127.0.0.1Servidor acessível a partir do próprio Windows.
Port5432Porta publicada pelo Docker.
Maintenance databaselaboratorioBanco criado ao inicializar o contêiner.
UsernamealunoUsuário definido no arquivo Compose.
PasswordAulaBD2026_Local!Senha didática do PostgreSQL.
  1. Clique em Save. Expanda Servers → PostgreSQL — Laboratório → Databases → laboratorio → Schemas → public.
  2. Selecione o banco laboratorio e abra Tools → Query Tool para executar SQL.
Se o acesso falhar

Confira primeiro o Docker Desktop e docker compose ps. O endereço 127.0.0.1 funciona porque o pgAdmin está instalado no mesmo Windows que publica a porta do contêiner.

5 · Primeiro teste

Crie uma tabela e execute consultas

Comece conferindo a conexão. No Query Tool, selecione o texto e use o botão de execução (ícone de ▶) para rodar a instrução.

SQL · confirme o servidor conectado
SELECT current_database() AS banco,
       current_user AS usuario,
       version();

Depois, use um exemplo simples relacionado à logística. Execute cada bloco uma vez, na ordem apresentada.

SQL · crie a tabela
CREATE TABLE centro_distribuicao (
    id_centro INTEGER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    nome VARCHAR(80) NOT NULL,
    cidade VARCHAR(80) NOT NULL,
    capacidade_diaria INTEGER NOT NULL CHECK (capacidade_diaria > 0)
);
SQL · insira quatro registros
INSERT INTO centro_distribuicao (nome, cidade, capacidade_diaria)
VALUES
    ('CD Curitiba Norte', 'Curitiba', 600),
    ('CD Curitiba Sul', 'Curitiba', 800),
    ('CD São José', 'São José dos Pinhais', 650),
    ('CD Londrina', 'Londrina', 500);
SQL · consulte os registros
SELECT id_centro, nome, cidade, capacidade_diaria
FROM centro_distribuicao
ORDER BY id_centro;

O resultado deve apresentar os quatro centros cadastrados. No navegador de objetos do pgAdmin, clique com o botão direito em Tables e escolha Refresh se a nova tabela ainda não aparecer.

Retomada da Aula 09: agregação e agrupamento

SQL · agrupar centros por cidade
SELECT cidade,
       COUNT(*) AS total_centros,
       SUM(capacidade_diaria) AS capacidade_total
FROM centro_distribuicao
GROUP BY cidade
ORDER BY capacidade_total DESC;

Arquivo SQL pronto

Você também pode abrir o script completo de teste (.sql) no Query Tool. Se já tiver criado a tabela, não execute novamente os comandos de criação e inserção: eles foram preparados para o primeiro teste.

6 · Uso no dia a dia

Parar, iniciar e preservar o banco

Execute os comandos na mesma pasta que contém o compose.yaml.

ComandoEfeito
docker compose stopPara o servidor sem remover o contêiner nem o volume.
docker compose startReinicia o contêiner já criado.
docker compose up -dCria ou inicia os serviços definidos no arquivo.
docker compose psMostra o estado do serviço.
docker compose logs --tail=30 dbExibe mensagens recentes do PostgreSQL.
docker compose downRemove contêiner e rede, mas mantém o volume nomeado.
Cuidado com docker compose down -v

O parâmetro -v remove também o volume deste ambiente e apaga seus dados persistidos. Use somente se tiver certeza de que deseja reiniciar o laboratório do zero.

Teste a persistência: execute docker compose stop, depois docker compose start, reconecte no pgAdmin e consulte novamente centro_distribuicao.

7 · Diagnóstico

Problemas comuns e como verificar

ProblemaO que verificar
docker não é reconhecidoConfirme a instalação do Docker Desktop e abra um novo PowerShell.
Cannot connect to Docker daemonAbra o Docker Desktop e aguarde o mecanismo iniciar. Verifique docker info.
Erro de WSL 2 ou virtualizaçãoConfira wsl --version, as atualizações do WSL e a virtualização da máquina; em laboratório, solicite apoio da TI.
Port is already allocated: 5432Outra aplicação está usando a porta. Altere apenas a porta à esquerda no Compose para 127.0.0.1:5433:5432 e configure a porta 5433 no pgAdmin.
Connection refused no pgAdminVerifique se o contêiner está em execução, se está saudável e se o host é 127.0.0.1.
Password authentication failedConfira usuário, senha e banco. Se o volume já foi inicializado antes com outra senha, mudar o Compose não altera a senha armazenada.
relation ... already existsA tabela já foi criada. Não execute novamente o bloco CREATE TABLE; continue pela consulta.

Para diagnosticar, use primeiro docker compose ps e docker compose logs --tail=30 db. Evite apagar volumes como primeira tentativa de correção.
