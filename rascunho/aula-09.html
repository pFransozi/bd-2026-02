Anatomia da SQL que já utilizamos

A estrutura básica de uma consulta

Exemplo de retomada · reservas canceladas
SELECT s.nome AS sala, r.situacao
FROM reserva AS r
INNER JOIN sala AS s
    ON s.id_sala = r.id_sala
WHERE r.situacao = 'cancelada'
ORDER BY s.nome;
TrechoO que determina?
SELECTQuais colunas ou expressões serão mostradas.
FROMDe qual tabela partimos.
JOIN ... ONComo relacionar linhas de outras tabelas.
WHEREQuais linhas atendem à condição.
ORDER BYComo ordenar as linhas devolvidas.

Agora acrescentaremos: funções no SELECT para calcular valores, GROUP BY para formar grupos, HAVING para filtrá-los e subconsultas para obter critérios a partir de outros SELECTs.

3 · Funções de agregação

Calcular um valor a partir de várias linhas

Em vez de listar cada ocorrência, uma função de agregação calcula um resultado sobre um conjunto de registros. Sem GROUP BY, a agregação considera todas as linhas que passaram pelo filtro.

FunçãoO que devolve
COUNT(*)Quantidade de linhas, incluindo aquelas com valores NULL em alguma coluna.
COUNT(coluna)Quantidade de valores não nulos naquela coluna.
SUM(coluna)Soma dos valores numéricos não nulos.
AVG(coluna)Média dos valores numéricos não nulos.
MIN(coluna) / MAX(coluna)Menor / maior valor.

3.1 · Quantas reservas e quantos usuários participaram?

Uma linha de resultado resume 20 reservas.

SQL · contagem de registros e de valores distintos
SELECT
    COUNT(*) AS total_reservas,
    COUNT(DISTINCT id_usuario) AS usuarios_com_reserva,
    COUNT(observacao) AS com_observacao
FROM reserva;
Resultado da consulta1 linha
total_reservasusuarios_com_reservacom_observacao
201111

COUNT(*) conta 20 linhas. COUNT(DISTINCT id_usuario) conta 11 usuários diferentes. COUNT(observacao) não conta os nove registros em que a observação é NULL.

3.2 · Qual é a capacidade das salas do Bloco B?

Uma combinação de funções numéricas aplicada apenas às três salas do bloco.

SQL · soma, média, menor e maior capacidade
SELECT
    SUM(capacidade) AS soma_capacidades,
    AVG(capacidade) AS media_capacidade,
    MIN(capacidade) AS menor,
    MAX(capacidade) AS maior
FROM sala
WHERE id_bloco = 2;
Resultado da consulta1 linha
soma_capacidadesmedia_capacidademenormaior
248.0414

O WHERE seleciona as salas do Bloco B antes de as funções calcularem os resultados.

4 · GROUP BY e HAVING

Produzir um resultado para cada grupo

Uma agregação sem GROUP BY produz um resumo geral. Com GROUP BY, as linhas são separadas por valores comuns e cada grupo recebe sua própria agregação.

4.1 · Quantas reservas existem em cada situação?

SQL · agrupamento por situação
SELECT situacao, COUNT(*) AS total
FROM reserva
GROUP BY situacao
ORDER BY situacao;
Resultado da consulta3 grupos
situacaototal
ativa12
cancelada3
concluida5

O banco continua com 20 reservas, mas o resultado agora tem uma linha para cada valor distinto de situacao. A coluna total indica o tamanho de cada grupo.

4.2 · A diferença entre WHERE e HAVING

WHERE seleciona linhas antes da formação dos grupos. HAVING seleciona grupos depois da agregação.

SQL · reservas a partir de 12/10 e grupos com pelo menos 3 registros
SELECT situacao, COUNT(*) AS total
FROM reserva
WHERE data >= '2026-10-12'
GROUP BY situacao
HAVING COUNT(*) >= 3
ORDER BY situacao;
Resultado da consulta2 grupos
situacaototal
ativa7
concluida3
FROM→WHERE (linhas)→GROUP BY (grupos)→HAVING (grupos)→SELECT→ORDER BY

O agrupamento cancelada tinha duas reservas a partir de 12/10, por isso foi eliminado pelo HAVING.

4.3 · Agregação com JOIN: quais salas foram reservadas pelo menos duas vezes?

O JOIN associa cada reserva à sua sala. O GROUP BY reúne as reservas da mesma sala; o HAVING mantém apenas os grupos que atendem à condição.

SQL · junção, contagem e filtragem de grupos
SELECT
    s.nome AS sala,
    COUNT(r.id_reserva) AS total_reservas
FROM sala AS s
LEFT JOIN reserva AS r
    ON r.id_sala = s.id_sala
GROUP BY s.id_sala, s.nome
HAVING COUNT(r.id_reserva) >= 2
ORDER BY total_reservas DESC, s.nome;
Resultado da consulta7 salas
salatotal_reservas
Sala Araucária3
Sala Horizonte3
Sala Ipê3
Laboratório Maker2
Sala Cedro2
Sala Gralha Azul2
Sala Inovação2

Em um LEFT JOIN, prefira COUNT(r.id_reserva) quando quiser contar reservas reais: a Sala Jacarandá não possui reservas e teria contagem zero. COUNT(*) contaria a linha preservada pela junção.

5 · Subconsultas

Utilizar uma consulta como parte de outra

Uma subconsulta é um SELECT dentro de outra instrução. Ela pode fornecer um valor, um conjunto de valores ou testar a existência de registros. Vamos observar três usos essenciais.

5.1 · Subconsulta escalar: salas acima da capacidade média

A consulta interna calcula uma média. A externa compara a capacidade de cada sala com esse valor.

SQL · um valor calculado por outra consulta
SELECT nome, capacidade
FROM sala
WHERE capacidade > (
    SELECT AVG(capacidade)
    FROM sala
)
ORDER BY capacidade DESC, nome;
Resultado da consulta5 salas
nomecapacidade
Sala Inovação30
Laboratório Sul24
Sala Imbuia20
Sala Jacarandá18
Laboratório Maker16

A média calculada pela consulta interna é aproximadamente 14,73. A consulta externa retorna somente as salas com capacidade superior a esse número.

5.2 · IN e EXISTS: usuários com reserva concluída

As duas consultas abaixo respondem à mesma pergunta por caminhos diferentes. Em IN, comparamos o identificador a um conjunto de valores; em EXISTS, verificamos se existe uma reserva correspondente.

SQL · subconsulta com IN
SELECT nome
FROM usuario
WHERE id_usuario IN (
    SELECT id_usuario
    FROM reserva
    WHERE situacao = 'concluida'
)
ORDER BY nome;
SQL · subconsulta com EXISTS
SELECT u.nome
FROM usuario AS u
WHERE EXISTS (
    SELECT 1
    FROM reserva AS r
    WHERE r.id_usuario = u.id_usuario
      AND r.situacao = 'concluida'
)
ORDER BY u.nome;
Resultado das duas consultas5 usuários
nome
Beatriz Lima
Camila Freitas
Gustavo Neri
Larissa Moura
Marina Lopes

Na versão com EXISTS, a condição r.id_usuario = u.id_usuario relaciona a subconsulta à linha da consulta externa. SELECT 1 é usado porque interessa saber se existe ao menos uma linha, não recuperar suas colunas.

5.3 · NOT EXISTS: salas sem nenhuma reserva

Com NOT EXISTS, selecionamos linhas para as quais a subconsulta não encontra correspondências.

SQL · ausência de registros relacionados
SELECT s.nome
FROM sala AS s
WHERE NOT EXISTS (
    SELECT 1
    FROM reserva AS r
    WHERE r.id_sala = s.id_sala
)
ORDER BY s.nome;
Resultado da consulta1 sala
nome
Sala Jacarandá

Para a Sala Jacarandá, a subconsulta não encontra nenhuma reserva. Por isso, a linha é mantida pela condição NOT EXISTS.

Agora formule as consultas

Use a mesma base de dados da Aula 08. Para cada pergunta, identifique as tabelas e escreva uma consulta SQL. Confira se os resultados fazem sentido.

1 · Contagem

Quantas reservas possuem uma observação preenchida? Use uma função de agregação e um alias claro.

2 · Agrupamento

Quantas reservas existem para cada usuário? Mostre o nome e inclua usuários que ainda não fizeram reservas.

3 · HAVING

Quais situações aparecem em pelo menos quatro reservas? Mostre a situação e a quantidade.

4 · Subconsulta escalar

Quais salas têm capacidade menor que a capacidade média de todas as salas? Ordene pela capacidade.

Quais usuários ainda não realizaram nenhuma reserva?

Síntese da estrutura

Ordem de escrita das cláusulas usadas nesta aula
SELECT coluna_agrupada, COUNT(*) AS total
FROM tabela
JOIN outra_tabela ON condicao_de_juncao
WHERE condicao_sobre_linhas
GROUP BY coluna_agrupada
HAVING COUNT(*) >= 2
ORDER BY total DESC;

Este último bloco é um modelo de estrutura, não uma consulta executável no banco de reservas. Subconsultas podem aparecer dentro de expressões como as condições do WHERE.
