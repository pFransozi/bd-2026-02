0 · Preparando o ambiente

Antes de usar DML, o banco precisa existir

O notebook executa Python. Para acessar um banco usamos um driver; nesta aula, o módulo sqlite3. Abrir a conexão cria o arquivo do banco, mas não cria automaticamente as tabelas. Por isso vamos preparar a conexão e carregar a estrutura antes do primeiro INSERT.

Notebook / Python→sqlite3→arquivo .db→tabelas→DML

Python

Executa as células do notebook.

sqlite3

É o driver/conector que permite ao Python enviar SQL ao SQLite.

SQLite

Armazena o banco em um arquivo e executa os comandos SQL enviados pelo notebook.

Célula 1

Abra a conexão e ative as chaves estrangeiras

Execute esta célula no início da aula.

Python · conexão
import sqlite3

conexao = sqlite3.connect("reserva_salas.db")
cursor = conexao.cursor()

cursor.execute("PRAGMA foreign_keys = ON;")

print("Conexão aberta.")
Importante

sqlite3.connect(...) cria o arquivo se ele não existir. Nesse momento o arquivo ainda pode estar vazio: nenhuma tabela foi criada apenas por abrir a conexão.

Célula 2 · preparação do laboratório

Crie a estrutura que vamos usar durante a prática

O conteúdo de hoje não é reaprender CREATE TABLE. A célula abaixo apenas reconstrói, de uma vez, o esquema que já conhecemos e acrescenta algumas restrições que serão testadas durante a aula. Execute a célula inteira antes de começar os INSERTs.

Python · criando as tabelas do laboratório
cursor.executescript("""
DROP TABLE IF EXISTS reserva;
DROP TABLE IF EXISTS telefone_usuario;
DROP TABLE IF EXISTS sala;
DROP TABLE IF EXISTS usuario;
DROP TABLE IF EXISTS bloco;

CREATE TABLE usuario (
    id_usuario INTEGER PRIMARY KEY,
    nome TEXT NOT NULL
);

CREATE TABLE telefone_usuario (
    id_usuario INTEGER NOT NULL,
    telefone TEXT NOT NULL,
    PRIMARY KEY (id_usuario, telefone),
    FOREIGN KEY (id_usuario)
        REFERENCES usuario(id_usuario)
        ON DELETE CASCADE
);

CREATE TABLE bloco (
    id_bloco INTEGER PRIMARY KEY,
    nome_bloco TEXT NOT NULL UNIQUE
);

CREATE TABLE sala (
    id_sala INTEGER PRIMARY KEY,
    nome TEXT NOT NULL,
    capacidade INTEGER NOT NULL CHECK (capacidade > 0),
    id_bloco INTEGER NOT NULL,
    FOREIGN KEY (id_bloco)
        REFERENCES bloco(id_bloco)
        ON DELETE RESTRICT
);

CREATE TABLE reserva (
    id_reserva INTEGER PRIMARY KEY,
    id_usuario INTEGER NOT NULL,
    id_sala INTEGER NOT NULL,
    data TEXT NOT NULL,
    hora_inicio TEXT NOT NULL,
    situacao TEXT NOT NULL DEFAULT 'ativa'
        CHECK (situacao IN ('ativa', 'cancelada', 'concluida')),

    UNIQUE (id_sala, data, hora_inicio),
    FOREIGN KEY (id_usuario)
        REFERENCES usuario(id_usuario)
        ON DELETE RESTRICT,
    FOREIGN KEY (id_sala)
        REFERENCES sala(id_sala)
        ON DELETE RESTRICT
);
""")

conexao.commit()
print("Estrutura criada.")
Ao executar novamente, os dados anteriores serão apagados

Os comandos DROP TABLE IF EXISTS servem para deixar todos os estudantes no mesmo ponto de partida. Use esta célula para reiniciar o laboratório quando necessário.

Célula 3

Confirme que as tabelas realmente existem

Antes de inserir qualquer dado, vamos verificar o catálogo interno do SQLite.

Python · conferindo a estrutura
cursor.execute("""
SELECT name
FROM sqlite_master
WHERE type = 'table'
ORDER BY name;
""")

for tabela in cursor.fetchall():
    print(tabela[0])
Resultado esperado

Devem aparecer bloco, reserva, sala, telefone_usuario e usuario. Só depois dessa conferência começaremos o DML.

Uma ajuda para os testes

Vamos criar duas funções pequenas

Elas não substituem o SQL. Apenas evitam repetir o código Python de conexão a cada exemplo e mantêm a aula focada nos comandos do banco.

Python · executar e consultar
def executar(sql):
    try:
        cursor.execute(sql)
        conexao.commit()
        print("✓ Operação executada")
    except sqlite3.Error as erro:
        conexao.rollback()
        print("✗ Erro:", erro)


def consultar(sql):
    cursor.execute(sql)
    colunas = [descricao[0] for descricao in cursor.description]
    linhas = cursor.fetchall()
    print(colunas)
    for linha in linhas:
        print(linha)

SALA depende de BLOCO; TELEFONE_USUARIO depende de USUARIO; RESERVA dependerá de USUARIO e SALA. A ordem dos INSERTs acompanha as FKs.

4 · UPDATE e DELETE

Primeiro localize. Depois modifique.

Para alterar ou excluir com segurança, vamos adotar uma rotina simples: SELECT → conferir → UPDATE/DELETE → SELECT novamente.

UPDATE

Cancele a reserva que criamos

1 · localize
consultar("""
SELECT *
FROM reserva
WHERE id_reserva = 1;
""")
2 · altere
executar("""
UPDATE reserva
SET situacao = 'cancelada'
WHERE id_reserva = 1;
""")
3 · confira
consultar("""
SELECT *
FROM reserva
WHERE id_reserva = 1;
""")
Analise, mas não execute agora

UPDATE reserva SET situacao = 'cancelada'; não possui WHERE. O comando é válido e pode alterar todas as reservas.

DELETE

Excluir também exige saber exatamente o que será atingido

Antes de apagar uma ocorrência, localize-a com a mesma condição.

1 · localize
consultar("""
SELECT *
FROM telefone_usuario
WHERE id_usuario = 42;
""")
2 · exclua um telefone
executar("""
DELETE FROM telefone_usuario
WHERE id_usuario = 42
  AND telefone = '41984327710';
""")
3 · confira
consultar("SELECT * FROM telefone_usuario;")
E se tentarmos excluir um registro referenciado?

A reserva de id 1 continua ligada ao usuário 17 e à sala 204. Tente prever o que acontecerá se executarmos DELETE FROM usuario WHERE id_usuario = 17;. A FK da reserva está configurada com ON DELETE RESTRICT, portanto a operação deve ser rejeitada enquanto a reserva existir.

Desafio em dupla · uma pequena história no banco
