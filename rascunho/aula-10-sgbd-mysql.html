1 · Conceitos fundamentais

Banco de dados, SGBD e SQL

Embora os termos sejam usados informalmente como sinônimos, eles designam elementos diferentes da arquitetura.

Onde entra o InnoDB?

O MySQL é um SGBD relacional com arquitetura cliente-servidor. O servidor autentica as conexões, analisa SQL e escolhe como executar cada consulta. Para acessar as tabelas, ele utiliza um mecanismo de armazenamento.

O InnoDB é o mecanismo padrão do MySQL. Ele organiza os dados em páginas e índices e oferece chaves estrangeiras, transações e controle de concorrência. Na prática, ENGINE=InnoDB torna explícito o mecanismo usado pelas tabelas de reserva.

O que um SGBD acrescenta a um conjunto de arquivos?

Os arquivos armazenam os dados, mas o gerenciamento confiável exige mecanismos adicionais. No MySQL, essas responsabilidades são concentradas no SGBD, que coordena como as informações são organizadas, consultadas, protegidas e recuperadas.

2 · Arquitetura e processamento

O que acontece entre executar um SELECT e receber o resultado?

O MySQL Workbench e a aplicação Python enviam SQL ao mesmo servidor. O servidor interpreta e planeja a consulta, acessa as tabelas pelo InnoDB e devolve as linhas ao cliente.

As etapas do processo

01 · Conexão

Python e Connector/Python

O código utiliza mysql.connector.connect() para abrir uma conexão. O driver implementa a comunicação entre a aplicação e o servidor.

02 · Envio

SQL parametrizada

O cursor envia a instrução com execute(sql, params). Parâmetros são passados separadamente do texto SQL.

03 · Análise

Interpretação e validação

O MySQL verifica sintaxe, referências a objetos, tipos e permissões necessárias.

04 · Planejamento

Estratégia de execução

O otimizador compara planos e estima custos, podendo escolher varredura sequencial, índices e diferentes algoritmos de junção.

05 · Execução

Acesso aos dados

O executor solicita os registros ao InnoDB. O mecanismo acessa páginas e índices e aplica as regras de visibilidade da transação.

06 · Retorno

Linhas no Python

O resultado volta ao programa, que pode recuperar uma linha com fetchone() ou todas as linhas restantes com fetchall().

Exemplo de uma consulta SQL executada pelo Python

O MySQL Connector/Python fornece a biblioteca mysql.connector. O exemplo consulta as salas com pelo menos 30 lugares e indica o bloco de cada sala.

Instalação das dependênciasTerminal
python -m pip install mysql-connector-python python-dotenv
Python · conexão, SELECT e retorno de linhasConnector/Python
import os

import mysql.connector
from dotenv import load_dotenv

load_dotenv()

with mysql.connector.connect(
    host=os.getenv("MYSQL_HOST", "127.0.0.1"),
    port=int(os.getenv("MYSQL_PORT", "3306")),
    database=os.getenv("MYSQL_DATABASE", "pratica_salas"),
    user=os.getenv("MYSQL_USER", "aluno"),
    password=os.getenv("MYSQL_PASSWORD", ""),
) as conn, conn.cursor() as cur:
    cur.execute(
        """
        SELECT s.nome AS sala,
               b.nome_bloco AS bloco,
               s.capacidade
        FROM sala AS s
        JOIN bloco AS b ON b.id_bloco = s.id_bloco
        WHERE s.capacidade >= %s
        ORDER BY s.nome
        """,
        (30,),
    )

    for sala, bloco, capacidade in cur.fetchall():
        print(f"{sala} ({bloco}) tem {capacidade} lugares")

Execute o exemplo depois de criar as tabelas e preparar o .env na prática guiada. A conexão utiliza MYSQL_HOST, MYSQL_PORT, MYSQL_DATABASE, MYSQL_USER e MYSQL_PASSWORD.

Como o valor 30 chega ao SQL? O marcador %s indica a posição do parâmetro. O driver associa o valor recebido em (30,), uma tupla de um elemento. Assim, o valor digitado entra como dado da consulta.

Principais funções e métodos do Connector/Python

O objeto de conexão representa a sessão com o servidor. O cursor envia os comandos e percorre os resultados.

Como os dados são armazenados?

A aplicação vê tabelas, colunas e registros. No InnoDB, os registros são organizados em páginas do índice da chave primária. O buffer pool mantém em memória páginas de dados e índices usadas nas leituras e escritas.

Visão lógica

Banco (esquema) → tabela → linha/coluna. No MySQL, DATABASE e SCHEMA nomeiam a mesma estrutura.

Visão física

Páginas de dados e índices, arquivos e memória. O InnoDB gerencia a passagem das páginas entre o disco e o buffer pool.

Essa separação é uma forma de independência de dados: aplicações normalmente não precisam conhecer a posição física de cada registro.

Pergunta de análise

Se duas consultas devolvem as mesmas linhas, como o MySQL escolhe por onde começar?

O otimizador compara alternativas de acesso com base nos índices e nas estatísticas. A ordem das junções e a quantidade de linhas estimadas podem mudar o plano.

3.1 · Integridade: impedir estados inválidos

Ao definir CHECK (capacidade BETWEEN 1 AND 80) na tabela sala, impedimos capacidades inválidas. Uma chave estrangeira na tabela reserva impede que uma reserva seja associada a um usuário ou a uma sala inexistente.

Outras regras exigem uma modelagem apropriada. Por exemplo, UNIQUE (id_sala, data_reserva, hora_inicio) impede que a mesma sala seja reservada duas vezes para a mesma data e hora de início.

3.2 · Transações: uma unidade lógica de trabalho

Use START TRANSACTION para agrupar alterações em tabelas InnoDB. Com autocommit ativo, uma alteração bem-sucedida fora de uma transação explícita é confirmada ao terminar a instrução.

Nos testes de ROLLBACK, mantenha apenas operações de dados na transação. Comandos DDL como CREATE TABLE e ALTER TABLE provocam confirmação implícita no MySQL.

COMMIT

Confirma as alterações da transação, tornando-as permanentes segundo as garantias configuradas.

ROLLBACK

Desfaz as alterações não confirmadas da transação.

As quatro propriedades ACID

PropriedadeSignificado didáticoNo sistema de reservas
AtomicidadeAs alterações da transação são confirmadas ou desfeitas como uma unidade.Não confirmar alterações parciais de uma reserva.
ConsistênciaPreservar os invariantes e restrições efetivamente declarados.Uma reserva deve referenciar uma sala existente e respeitar as restrições do esquema.
IsolamentoControlar como transações concorrentes observam ou interferem nos dados.Duas tentativas simultâneas de reservar o mesmo horário precisam ser coordenadas.
DurabilidadeManter alterações confirmadas apesar de falhas, dentro das garantias configuradas.Uma reserva confirmada deve permanecer registrada após uma falha.

3.3 · Índices e processamento de consultas

Um índice é uma estrutura auxiliar utilizada para localizar registros com menos trabalho em determinadas consultas. Ele pode acelerar filtros seletivos, mas ocupa espaço e precisa ser mantido quando os dados mudam.

Observar o plano antes de otimizarSQL
EXPLAIN FORMAT=TRADITIONAL
SELECT id_sala, nome, capacidade
FROM sala
WHERE id_sala = 1;

Na saída tabular, key mostra o índice escolhido, type descreve o acesso e rows indica quantas linhas o otimizador estima examinar. Na busca pela chave primária, espere key = PRIMARY e type = const para uma sala existente. Um acesso ALL percorre a tabela.

EXPLAIN descreve o plano estimado. A partir do MySQL 8.0.18, EXPLAIN ANALYZE executa a consulta e registra tempos e quantidades de linhas observados.

3.4 · Segurança: autenticação e autorização

Autenticação responde “quem está tentando acessar?”. Autorização responde “o que essa identidade pode fazer?”. No MySQL, uma conta tem a forma 'usuario'@'host'. Ela recebe privilégios diretamente ou por meio de papéis, que agrupam permissões.

Exemplo de autorização · requer privilégios administrativosSQL
CREATE ROLE 'consulta_salas';
GRANT SELECT ON pratica_salas.sala TO 'consulta_salas';
GRANT SELECT ON pratica_salas.reserva TO 'consulta_salas';
REVOKE SELECT ON pratica_salas.reserva FROM 'consulta_salas';
O exemplo concede leitura em duas tabelas e depois retira a concessão para reserva. Na prática, você consultará os privilégios da sua conta com SHOW GRANTS.

O SGBD pode restringir operações, mas a segurança do sistema também depende da aplicação, da rede, das credenciais e das práticas de desenvolvimento.

3.5 · Recuperação após falhas e restauração

Após uma interrupção, o InnoDB usa o redo log para refazer alterações necessárias às páginas e desfaz transações que ficaram incompletas. Recuperar registros excluídos por engano exige uma estratégia de restauração.

Redo log

Registra mudanças para que o InnoDB possa reaplicá-las durante a recuperação após uma falha.

Backup

Uma exportação lógica com mysqldump pode ser restaurada com o cliente mysql.

Binary log

Registra mudanças para replicação e, em conjunto com um backup, permite recuperar a base até um ponto no tempo.

Discussão

Uma exclusão por engano chegou à réplica. Como restaurar as reservas até o instante anterior à exclusão?

Restaure um backup e reaplique os eventos posteriores do binary log até o ponto imediatamente anterior à exclusão.

3.6 · Recursos para além da SQL básica

Views dão um nome a uma consulta reutilizável. Funções e procedimentos organizam rotinas, e triggers disparam ações em eventos como INSERT e UPDATE. O MySQL também oferece o tipo JSON para dados semiestruturados.

A escolha de onde implementar uma regra depende dos requisitos de integridade, manutenção e desempenho da aplicação.

4 · Concorrência

Por que várias pessoas podem consultar e atualizar ao mesmo tempo?

Em um sistema web, requisições chegam simultaneamente. O MySQL precisa coordenar esse trabalho sem tornar todas as operações uma única fila.

MVCC: múltiplas versões dos dados

O InnoDB usa MVCC (Multiversion Concurrency Control) para oferecer leituras consistentes. Quando uma consulta precisa enxergar uma versão anterior de um registro, o InnoDB pode reconstruí-la com informações do undo log. O nível de isolamento determina quais versões são visíveis.

Leituras comuns podem prosseguir enquanto outra transação escreve. Quando duas transações tentam inserir a mesma chave única, a segunda aguarda a primeira confirmar ou desfazer a inserção.

Transação AReserva a sala 2 às 15h
↔
InnoDBVersões, bloqueios e restrições
↔
Transação BTenta reservar a mesma sala e horário

O gerenciamento de concorrência combina visibilidade de versões, coordenação de conflitos e verificação das restrições.

O erro de separar verificação e reserva

Estratégia frágil · verificação seguida de uma operação independenteExemplo
SELECT COUNT(*) AS reservas_existentes
FROM reserva
WHERE id_sala = 2
  AND data_reserva = '2026-11-20'
  AND hora_inicio = '15:00:00';

-- A aplicação decide, depois, se fará INSERT.

Se duas aplicações consultarem o horário ao mesmo tempo, ambas poderão encontrar zero reservas. Essa leitura, isoladamente, não garante exclusividade: outra transação pode registrar uma reserva antes da inserção.

Uma inserção protegida pela restrição de unicidade

Reserva de sala · conflito verificado pelo SGBDSQL
INSERT INTO reserva
    (id_sala, id_usuario, data_reserva, hora_inicio, finalidade)
VALUES
    (2, 1, '2026-11-20', '15:00:00', 'Solicitação A');

A restrição UNIQUE (id_sala, data_reserva, hora_inicio) protege a reserva. Se a primeira inserção for confirmada, o segundo INSERT recebe o erro 1062 (Duplicate entry). A aplicação pode interpretar esse erro como horário indisponível.

Por que a regra funciona? Cada reserva ocupa uma hora e começa em hora cheia. Assim, a combinação sala, data e início identifica um horário completo. Reservas com duração variável exigiriam tratar a sobreposição de intervalos.

5 · Usos e decisões de projeto

Quando um SGBD é uma boa escolha?

Quando precisamos de mais do que armazenar registros: garantir operações corretas, coordenar acessos, recuperar informações e consultar dados com eficiência.

O MySQL é especialmente adequado quando precisamos de um SGBD cliente-servidor com múltiplas conexões e administração centralizada.

6 · Síntese

O papel do SGBD na arquitetura do software

O MySQL interpreta comandos, coordena acessos simultâneos e delega ao InnoDB o acesso aos dados e o gerenciamento das transações das tabelas da prática.

O SGBD faz

Executa consultas, verifica restrições declaradas, controla transações, gerencia concorrência, administra permissões e oferece recuperação.

O projeto precisa definir

Regras do domínio, esquema e índices, transações corretas, políticas de acesso, estratégias de backup e requisitos de operação.
