Visão da aula

O que vamos desenvolver

A aula será construída a partir de perguntas sobre o sistema de reserva de salas. Para cada pergunta, vamos identificar de quais tabelas vêm os dados, quais colunas precisamos, quais registros devem permanecer e como expressar isso em SQL.

  • Aplicar filtros com operadores relacionais e lógicos.
  • Utilizar IN, BETWEEN, LIKE, IS NULL e IS NOT NULL.
  • Ordenar resultados com ORDER BY.
  • Combinar tabelas relacionadas com INNER JOIN.
  • Relacionar seleção, projeção, produto cartesiano, junção, união e diferença às consultas SQL.

Célula 3

Use a mesma função de consulta

Ela recebe uma instrução SQL, mostra os nomes das colunas e imprime as linhas retornadas.

Python · função de apoio
def consultar(sql):
    cursor.execute(sql)
    colunas = [descricao[0] for descricao in cursor.description]
    linhas = cursor.fetchall()

    print(colunas)
    for linha in linhas:
        print(linha)
Teste inicial
consultar("SELECT * FROM usuario;")
Antes de avançar

Devem aparecer seis usuários. Se o resultado estiver correto, o laboratório está pronto.

1 · SELECT e FROM

Comece pela pergunta, não pelo comando

Uma consulta nasce de uma necessidade de informação. Antes de escrever SQL, formule a pergunta e identifique a tabela onde os dados estão armazenados.

Pergunta

Quais usuários existem no sistema?

Precisamos de dados da tabela usuario.

Consulta 1 · todas as colunas
consultar("""
SELECT *
FROM usuario;
""")
Leia a consulta de cima para baixo

SELECT indica o que queremos no resultado. FROM indica de onde os dados serão obtidos. O asterisco representa todas as colunas da tabela.

Nova pergunta

Quero apenas os nomes dos usuários.

Agora não precisamos de todas as colunas.

Consulta 2 · escolhendo colunas
consultar("""
SELECT nome
FROM usuario;
""")

Aliases

O resultado também pode ser apresentado com nomes mais claros

AS · nome temporário no resultado
consultar("""
SELECT
    id_usuario AS codigo,
    nome AS usuario
FROM usuario;
""")
O alias não altera a tabela

AS muda apenas o cabeçalho apresentado pela consulta. A coluna continua se chamando id_usuario no banco.

DISTINCT

Quando queremos valores diferentes, e não todas as ocorrências

Primeiro observe as repetições
consultar("""
SELECT situacao
FROM reserva;
""")
Agora remova as duplicidades do resultado
consultar("""
SELECT DISTINCT situacao
FROM reserva;
""")
Importante

DISTINCT não apaga dados. Ele apenas elimina linhas repetidas do resultado produzido pela consulta.

2 · WHERE

Nem sempre queremos todas as linhas

A cláusula WHERE representa uma condição. Apenas os registros para os quais a condição for satisfeita permanecem no resultado.

Pergunta

Quais salas comportam pelo menos 8 pessoas?

A tabela é sala. A condição envolve capacidade.

Filtro com operador relacional
consultar("""
SELECT nome, capacidade
FROM sala
WHERE capacidade >= 8;
""")
OperadorSignificadoExemplo
=igualsituacao = 'ativa'
<>diferentesituacao <> 'cancelada'
> / >=maior / maior ou igualcapacidade >= 8
< / <=menor / menor ou igualcapacidade < 10

AND, OR e NOT

Combine condições

Uma pergunta pode exigir mais de um critério ao mesmo tempo.

AND · as duas condições precisam ser verdadeiras
consultar("""
SELECT id_reserva, data, hora_inicio, situacao
FROM reserva
WHERE situacao = 'ativa'
  AND data = '2026-10-10';
""")
OR · basta uma das condições
consultar("""
SELECT id_reserva, situacao
FROM reserva
WHERE situacao = 'ativa'
   OR situacao = 'concluida';
""")
NOT · nega a condição
consultar("""
SELECT id_reserva, situacao
FROM reserva
WHERE NOT situacao = 'cancelada';
""")

Atalhos úteis de filtragem

IN, BETWEEN e LIKE

IN

Verifica se um valor pertence a um conjunto.

BETWEEN

Verifica se um valor está dentro de um intervalo, incluindo os limites.

LIKE

Procura padrões em textos usando curingas.

IN · mais legível que vários OR
consultar("""
SELECT id_reserva, situacao
FROM reserva
WHERE situacao IN ('ativa', 'concluida');
""")
BETWEEN · intervalo de capacidade
consultar("""
SELECT nome, capacidade
FROM sala
WHERE capacidade BETWEEN 6 AND 10;
""")
LIKE · nomes iniciados por M
consultar("""
SELECT id_usuario, nome
FROM usuario
WHERE nome LIKE 'M%';
""")
O curinga %

Em LIKE, % representa qualquer sequência de caracteres. Assim, 'M%' significa “começa com M”, enquanto '%a%' significa “contém a letra a em alguma posição”.

3 · NULL e ORDER BY

Ausência de valor não é a mesma coisa que um valor comum

Algumas reservas possuem uma observação; outras não. Quando não existe um valor conhecido para esse campo, o banco utiliza NULL.

Observe os valores
consultar("""
SELECT id_reserva, observacao
FROM reserva;
""")
Não use = NULL

NULL representa ausência ou desconhecimento. Por isso, a verificação é realizada com IS NULL ou IS NOT NULL.

Reservas sem observação
consultar("""
SELECT id_reserva, data, observacao
FROM reserva
WHERE observacao IS NULL;
""")
Reservas que possuem observação
consultar("""
SELECT id_reserva, observacao
FROM reserva
WHERE observacao IS NOT NULL;
""")

ORDER BY

Filtrar decide quem aparece. Ordenar decide em que sequência.

Salas da maior para a menor capacidade
consultar("""
SELECT nome, capacidade
FROM sala
ORDER BY capacidade DESC;
""")
Mais de um critério de ordenação
consultar("""
SELECT data, hora_inicio, id_sala, situacao
FROM reserva
ORDER BY data ASC, hora_inicio ASC;
""")
ASC e DESC

ASC ordena de forma crescente e é o padrão. DESC ordena de forma decrescente.

4 · Consultando mais de uma tabela

Uma reserva possui identificadores. A pergunta do usuário precisa de significado.

Observe a tabela reserva: ela armazena id_usuario e id_sala. Isso é suficiente para manter os relacionamentos, mas não é a forma mais útil de apresentar a informação para uma pessoa.

Comece vendo a tabela de reserva
consultar("""
SELECT id_reserva, id_usuario, id_sala, data, hora_inicio
FROM reserva;
""")
A pergunta agora é outra

Como mostrar o nome do usuário no lugar de apenas id_usuario? Esse dado está em outra tabela. Precisamos usar o relacionamento já definido entre usuario e reserva.

Antes do JOIN

Veja o que acontece quando combinamos tabelas sem dizer como elas se relacionam

Produto cartesiano · apenas para observar
consultar("""
SELECT COUNT(*) AS combinacoes
FROM usuario, reserva;
""")
6 usuários × 8 reservas = 48 combinações

Sem uma condição de relacionamento, cada usuário é combinado com cada reserva. A maioria dessas combinações não representa um fato do nosso domínio.

INNER JOIN

Use as chaves para recuperar somente as combinações relacionadas

Reserva + usuário
consultar("""
SELECT
    r.id_reserva,
    u.nome AS usuario,
    r.data,
    r.hora_inicio
FROM reserva AS r
INNER JOIN usuario AS u
    ON u.id_usuario = r.id_usuario;
""")
Leia o ON como uma regra de correspondência

Uma linha de reserva só é combinada com a linha de usuario cujo identificador é o mesmo valor armazenado na FK r.id_usuario.

Mais de uma junção

Monte uma resposta que faça sentido para o sistema

Agora queremos saber quem reservou, qual sala foi utilizada e em qual bloco ela está.

Reserva + usuário + sala + bloco
consultar("""
SELECT
    r.id_reserva,
    u.nome AS usuario,
    s.nome AS sala,
    b.nome_bloco AS bloco,
    r.data,
    r.hora_inicio,
    r.situacao
FROM reserva AS r
INNER JOIN usuario AS u
    ON u.id_usuario = r.id_usuario
INNER JOIN sala AS s
    ON s.id_sala = r.id_sala
INNER JOIN bloco AS b
    ON b.id_bloco = s.id_bloco
ORDER BY r.data, r.hora_inicio;
""")

JOIN + WHERE + ORDER BY

As cláusulas podem trabalhar juntas

Reservas ativas com nomes de usuário e sala
consultar("""
SELECT
    u.nome AS usuario,
    s.nome AS sala,
    r.data,
    r.hora_inicio
FROM reserva AS r
INNER JOIN usuario AS u
    ON u.id_usuario = r.id_usuario
INNER JOIN sala AS s
    ON s.id_sala = r.id_sala
WHERE r.situacao = 'ativa'
ORDER BY r.data, r.hora_inicio;
""")

5 · O que a álgebra relacional tem a ver com isso?

As consultas que executamos correspondem a operações sobre relações

A álgebra relacional fornece uma forma conceitual de pensar operações sobre tabelas. Nesta aula não vamos formalizar toda a notação; vamos reconhecer as ideias que já apareceram nas consultas.

Ideia da álgebra relacionalPerguntaCorrespondência que vimos em SQL
ProjeçãoQuais atributos queremos ver?Colunas listadas em SELECT
SeleçãoQuais tuplas devem permanecer?Condições em WHERE
Produto cartesianoO que acontece se combinarmos todas as linhas?Duas tabelas sem condição de relacionamento
JunçãoQuais linhas de relações diferentes correspondem entre si?INNER JOIN ... ON ...
UniãoQuais linhas pertencem a um conjunto ou a outro?UNION, quando os resultados são compatíveis
DiferençaQuais linhas estão em um conjunto e não estão no outro?EXCEPT no SQLite
Pergunta→relações envolvidas→projeção→seleção→junção→resultado

Dois testes rápidos

União e diferença na prática

Esses exemplos servem principalmente para tornar concretas duas operações de conjuntos.

UNION · usuários com reserva ativa ou concluída
consultar("""
SELECT id_usuario
FROM reserva
WHERE situacao = 'ativa'

UNION

SELECT id_usuario
FROM reserva
WHERE situacao = 'concluida';
""")
EXCEPT · usuários que ainda não possuem reserva
consultar("""
SELECT id_usuario
FROM usuario

EXCEPT

SELECT id_usuario
FROM reserva;
""")
Não transforme isso em memorização de comandos

O objetivo é perceber que uma consulta pode ser entendida como uma sequência de operações sobre conjuntos de linhas e colunas. Essa leitura ajuda a construir consultas mais complexas depois.

6 · Prática guiada

Pergunta → identifique os dados → escreva a consulta → confira o resultado

Continuamos no mesmo banco. Em cada etapa, leia primeiro a necessidade de informação e só depois execute a consulta.

1

Quais salas possuem capacidade para 6 ou mais pessoas?

Precisamos do nome e da capacidade. Depois, queremos visualizar primeiro as maiores salas.

consultar("""
SELECT nome, capacidade
FROM sala
WHERE capacidade >= 6
ORDER BY capacidade DESC;
""")
Modifique

Troque >= 6 por BETWEEN 6 AND 10. Quais salas deixam de aparecer?

2

Quais reservas estão ativas no dia 10/10?

Primeiro resolva usando apenas a tabela reserva.

consultar("""
SELECT id_reserva, id_usuario, id_sala, hora_inicio
FROM reserva
WHERE data = '2026-10-10'
  AND situacao = 'ativa'
ORDER BY hora_inicio;
""")
Resultado intermediário

A consulta responde corretamente, mas ainda mostra identificadores. No próximo passo vamos tornar a resposta mais útil.

3

Substitua os identificadores pelos nomes

A mesma pergunta agora deve mostrar o usuário e a sala.

consultar("""
SELECT
    u.nome AS usuario,
    s.nome AS sala,
    r.hora_inicio
FROM reserva AS r
INNER JOIN usuario AS u
    ON u.id_usuario = r.id_usuario
INNER JOIN sala AS s
    ON s.id_sala = r.id_sala
WHERE r.data = '2026-10-10'
  AND r.situacao = 'ativa'
ORDER BY r.hora_inicio;
""")
4

Localize reservas que precisam de complemento

Considere como “precisam de complemento” as reservas que não possuem observação.

consultar("""
SELECT id_reserva, data, hora_inicio, observacao
FROM reserva
WHERE observacao IS NULL
ORDER BY data, hora_inicio;
""")
5

Monte um painel simples das reservas ativas

Mostre usuário, sala, bloco, data e horário. Ordene por data e horário.

consultar("""
SELECT
    u.nome AS usuario,
    s.nome AS sala,
    b.nome_bloco AS bloco,
    r.data,
    r.hora_inicio
FROM reserva AS r
INNER JOIN usuario AS u
    ON u.id_usuario = r.id_usuario
INNER JOIN sala AS s
    ON s.id_sala = r.id_sala
INNER JOIN bloco AS b
    ON b.id_bloco = s.id_bloco
WHERE r.situacao = 'ativa'
ORDER BY r.data, r.hora_inicio;
""")
6

Agora altere a pergunta

Partindo da consulta anterior, faça três modificações, uma de cada vez:

  • mostre apenas reservas do Bloco A;
  • mostre apenas salas com capacidade entre 6 e 10;
  • mostre apenas usuários cujo nome contenha a letra a.
Nesta etapa não há uma consulta pronta

Use a estrutura já construída e altere apenas as condições necessárias. Execute uma mudança por vez para conseguir observar o efeito de cada filtro.

Síntese

Consultar é construir uma resposta a partir das relações

Hoje partimos de perguntas sobre o sistema e fomos refinando as consultas: primeiro escolhemos tabelas e colunas, depois filtramos e ordenamos linhas, tratamos ausência de valor e, por fim, combinamos relações diferentes por meio das chaves.
